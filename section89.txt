  ## 10. Security Considerations
  
  > **Note:** The current implementation uses session-based authentication suitable for an academic/prototype 
deployment. For full production hardening, the following upgrades are recommended.
  
  ### Current Implementation
  - Passwords stored as plain text in the database
  - Role verification is client-driven (trust role from login response)
  - Sessions maintained via Flask's cookie-based session store
  
  ### Recommended Production Upgrades
  
  | Area | Current | Recommended |
  |---|---|---|
  | Authentication | Plain text passwords | bcrypt hashing |
  | Authorization | Client-side role | JWT tokens with server-side verification |
  | Database | SQLite | PostgreSQL with connection pooling |
  | HTTPS | Not configured | SSL/TLS via Nginx + Let's Encrypt |
  | Secrets | Hardcoded | AWS Secrets Manager / Jenkins Credentials |
  | Session | Cookie-based | Stateless JWT / Redis session store |

  ### 11.2 Running Tests
  
  ```bash
  # Local development
  python -m pytest tests/ -v
  
  # With coverage report
  python -m pytest tests/ -v --cov=app --cov-report=html
  
  # Run a specific test file
  python -m pytest tests/test_auth.py -v
  
  # Run inside Docker container (CI mode)
  docker compose run --rm backend pytest tests/ -v
  ```
